# ARC Overhaul（ARC 大修）

[English](README.md)

独立于 Acbric 框架的功能 MOD，按功能逐步扩展。**0.1.0-dev.9** 实现征服开局城市数、城镇数、现金和研发点（**仅影响人类势力**），可以完全控制**大地图上出现哪些 AI 舰队**，并让 **T 指令能点名无武装的建筑与飞艇**。AI 保留原版初始数量与现金规则。地图布局及随机过程改变后，AI 的具体位置、资产组合不保证与原版同种子完全相同。

## 使用

需要 Acbric API **0.3.3-dev.21 或更新的兼容版本**、Java 21。退出游戏，把 `build/libs/ARC-Overhaul-0.1.0-dev.9.jar` 放进运行副本的 `game/mods/`。先停用旧 `acbric-starting-cities.jar` 并重启；两者声明互斥。不要安装 dev.1 骨架或测试夹具 JAR。

入口：**单人征服开局设置 → 将设置列表滚到最底部 → ARC 大修：玩家开局设置**。另可从 **MOD 列表 → ARC Overhaul → 详情** 打开。输入后点击“应用”，关闭窗口再开始新局。中英文跟随游戏语言。

同一个列表里还有第二个入口：**ARC 大修：AI 舰队**，见下文。

| 字段 | 自定义范围 | `-1` 含义 |
|---|---|---|
| 城市数 | 1–4 | 原版 1 座 |
| 城镇数 | 0–8 | 当前地图默认城镇数 |
| 现金 | 0–1,000,000 | 原版难度及初始资产结算后的余额 |
| 研发点 | 0–10,000,000 | `0` 不发放，等同原版 |

前三个字段默认 `-1`，研发点默认 `0`，可独立设置。城市数 `0` 无效，应用时拒绝；现金 `0` 表示零现金开局。现金在初始建筑/舰船配置后设置，不提高生成资产的预算。数量影响原生资产分配和玩法平衡。

研发点存入原生**未分配研发池**（`Empire.unassignedResearchPoints`），游戏会在你选定第一个研究时整池注入。写入 `Empire.researchPoints` 是无效的：原生「选择科技」命令会先用新科技在 `partialResearchPoints` 里的进度（全新科技即 0）覆盖该字段，之后才累加未分配池，所以点第一下科技时发放的点数就会被静默清空。取值范围刻意放在百万级：一项科技需要 `BASE_RESEARCH_COST × RESEARCH_COST_MULTIPLIER × 5600 × 1.4^tier` 点（`Tech.baseCost`），前几级约 2,240,000 点，更小的数值在进度条上根本看不出来。

新增定居点不会落在孤立陆地上：原生选址只要求落点不是水，因此 ARC 会重新选址，直到落点属于一块至少 `max(32, gridSize/4)` 格的连通陆地。重试次数有上限并会回退到最后一个候选落点，不会因此让生成失败。仅对自定义数量下的人类势力生效，AI 与默认设置保持原生结果。

飞机不会在攻击途中掉头：原生航线逻辑每趟只记一个世界坐标航点，目标离它 200px 就整块作废，再按「此刻在目标哪一侧」重选 —— 于是移动中的目标可能把飞机甩到反方向去，而轰炸机（五种飞机里加速度最低，且必须平飞穿过目标中间才能投弹）一趟白跑就是 0 伤害。ARC 现在让航点随目标一起平移，偏移量保持不变。机制与实测数据见 [CHANGELOG](CHANGELOG.zh-CN.md)。

T 指令可以点名**无武装**的目标：选中舰船按 T 再点敌方建筑或无武装飞艇，炮组会真的去打它。原版把「这个目标值得打吗」写成 `dangerCache > 0`（`Module.targetShip` 第 1464 行），而无武装的固定建筑在 `Airship.danger()` 里根本拿不到威胁值（`inCombat()` 为假），于是指令被静默忽略，炮组转头去打自己的自动目标。ARC 只在那几次「判定玩家点名的目标」的读取上把该值抬成正数，自动选目标仍完全按原版威胁值排序 —— 因此舰船与舰载机不会主动打无武装的东西，必须有人用 T 点名；手操（直控）模式本来就靠准星直接指定坐标，不受影响。

同一条规则也让**无武装航母**能用 T：出击的舰载机会继承母舰的 `fireAt`（`Crewman.outsideShootingTick` 第 2248 行），所以「选中航母 → T 点敌人」可以把飞机派去打这个目标。原版这条继承同样带着 `dangerCache > 0`，装填期间还会把继承来的目标清空；另外多选/框选时航母会被 `canShoot()` 过滤掉，指令根本发不出去，指令面板上的 T 按钮也因为同一个条件对无武器舰船永远是灰的。

判断「这艘船能不能下 T 指令」时，舰载机那一路**不能只看飞机指挥台**：`canGiveAircraftCommands()` 认的是 `ModuleType.canGivePlaneCommands`，游戏数据里只有 `FLIGHT_CENTRE` 有这个键，而机库（`BOMBER_HANGAR` 等六种）只声明 `quartersType`（机组的 `CrewType.canFly` 为真）。所以「只带机库、没有指挥台」的航母在那一项上是假，装上机库也点不亮 T 按钮。ARC 改用原版 `Airship.hasFlyers()` 把这类航母一并算进来；无武器、又没有飞机舱位的运输/登陆舰仍与原版一样被跳过。

数量上限暂时保守。位置不足时明确报错，不静默少生成；新增距离数组超过 128 MiB 也会拒绝，此限制不代表整个游戏的内存预算。

## AI 舰队

「AI 舰队」就是游戏里的 `ConstructionStrategy`：一个势力会使用哪些船、陆行舰、建筑和科技树。每局征服模式里，每个势力会从已加载的舰队中随机分到一支，只按该势力的军徽图案和难度过滤，玩家完全无法干预。**ARC 大修：AI 舰队** 会列出所有已加载的舰队，每支三态可选：

| 状态 | 效果 |
|---|---|
| 允许 | 可能被随机选中。这是默认值，与原版完全一致。 |
| 强制启用 | 从随机池里拿掉，改为强制分配给指定数量的国家。 |
| 强制禁用 | 永远不会出现在地图上。 |

出场国家数统计的是**非玩家**国家；你自己的国家始终保留原版舰队。因为被强制启用的舰队会离开随机池，填 `3` 得到的就是恰好 3 个国家，而不是“至少 3 个”。如果某个势力可用的舰队全部被禁用或占用，ARC 会保留原版选择，而不是让生成失败。默认设置下 ARC 在动任何东西之前就返回，不消耗随机数，同一种子仍然生成与原版一致的世界。

舰队按游戏加载时使用的名字列出，也就是 AI 舰队包里的名字。配置位于 `game/config/arc_overhaul/conquest-fleets.json`，只写入你改动过的舰队；来自临时停用 MOD 的条目会保留。

### 批量操作与出场国家数输入框

底部有 **全部强制禁用** 和 **全部强制启用**：一次点击标记所有已加载的舰队。「全部强制启用」沿用每支舰队当前的出场国家数（取不到时用上一次的有效值），不会把你已经填好的数字抹掉。

出场国家数输入框可以先清空再重输：它原样显示你输入的内容，包括空。空值既不算错误也不会被保存成 0，而是沿用上一次的有效数字；只有真的输错（不是数字，或不在 1–32 之间）才提示，并且在你改好之前无法应用。空框也会在你能观察到的下一次操作时复原成删除前的数字：在别的框里输入、点任何按钮、或点应用。

有两件小事**没有做**，因为它们需要改 Acbric 框架：输入框处于不可编辑状态时无法变灰（框架的画布适配层绘制文字时忽略 `enabled` 标志，并且刻意把方括号转义，MOD 无法注入游戏的富文本颜色指令）；以及「点进别的框而不输入就立刻复原」也做不到（框架切换焦点时没有任何回调）。动框架之前请先看改动记录里提到的框架版本情况。
## 存档与联机边界

- 配置位于 `game/config/arc_overhaul/conquest-start.json`（开局设置）与 `game/config/arc_overhaul/conquest-fleets.json`（AI 舰队），两者一起经 Acbric 共享规则在新战役开始时冻结，后续改配置不影响已有战役。
- 本版面向新战役。缺少 `arc_overhaul` 规则的旧档会被框架以 `RULE_MISSING` 阻止，不自动转换。玩旧档可停用 ARC 后重启；暂无 ARC 专属迁移工具。
- ARC 新档继续运行须保留 ARC。加载/恢复不重复分地或发钱；扩大 ID 容量的存档带有 `arcStartingLayout` 技术字段。
- 联机参与现有规则检查，但不自动广播房主配置。各方须在入厅前从 MOD 详情设置相同值。没有新增大厅编辑面板；完整联机生成/续局未验收，先测试单人。
- 不保证与其他世界生成 MOD 共存；框架源码、用户运行副本均未被本次构建覆盖。

## 构建

使用 JDK 21 和匹配的 Acbric API dev.21 构建，依赖与路径详见[协作开发指南](CONTRIBUTING.zh-CN.md)。框架基线提交为 `1be89b2`，不能假设上游默认分支已经包含。

```powershell
.\gradlew.bat build
# 覆盖默认的相邻 Acbric 目录及其中的游戏库路径：
.\gradlew.bat build -PacbricDir="D:/Development/Acbric" -PgameLibDir="D:/Games/Airships/libs"
```

输出：`build/libs/ARC-Overhaul-0.1.0-dev.9.jar`。安装时替换旧 ARC JAR，不要并存。产物不含游戏、框架或测试类，不自动安装。`build` 检查编译/打包，默认 `test` 无源码；[集成检查](TESTING.zh-CN.md#运行隔离检查windows)使用自有游戏输入单独运行。

PR #1 修复额外城镇领土缺色，用户已确认该修复实机正常。游戏 1.2.15.2 / 1.2.14 使用 API dev.25 各通过 407 项定向检查，合计 814：真实 Fabric 注入、原生放置/连续 ID、领土描边、现金一次性、配置和原生磁盘/内存保存恢复。纹章、背景与土地资源使用测试替身，描边使用合成归属网格；完整地图/道路/初始资产、GPU 与联机未获全面验证。见 [测试手册](TESTING.zh-CN.md)。

## 目录

- `src/main/java/net/poosh/arc/`：ARC 自有源码，后续按功能分包。
- `src/main/resources/fabric.mod.json`：MOD 身份与入口。
- `build/`：可重建的构建输出。
- [源码定位和设计边界](RESEARCH.zh-CN.md)：首个功能的实现依据与旧 MOD 对照。

玩法放在 `conquest/`，原生适配放在 `mixin/`。后续按功能独立扩展，不将玩法混入框架。
